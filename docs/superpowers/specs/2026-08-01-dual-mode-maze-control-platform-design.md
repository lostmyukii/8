# 双模式迷宫小车控制、定位、自动调参与回放平台设计

日期：2026-08-01  
状态：设计已逐段确认，待用户审阅本文后进入实施计划  
适用项目：RDK X3 + ESP32 迷宫小车  
公网入口：`https://8.ilelezhan.cn`

## 1. 文档定位

本文定义在现有 FastAPI Dashboard、Webots 仿真和 RDK X3/ESP32 控制链之上新增的网站平台。平台第一版同时支持：

1. Webots 仿真模式。
2. 真实 RDK X3 + ESP32 小车模式。
3. 一键重置、自动探索、实时观看、位置与方向显示、完成计分和全过程回放。
4. 手工描线创建规则格子迷宫，并可导入实体迷宫图片辅助描摹。
5. 手动调参、规则型自动调参、模型建议、仿真批量优化和参数版本管理。

本文对 `2026-08-01-cpu-webots-cloud-deployment-design.md` 的后续网站阶段作增量替代。特别是：

- SSH 密码登录按用户最新决定继续保留，同时启用专用公钥。
- 网站通过已备案域名和 HTTPS 对外提供，替代“仅使用 SSH 隧道”的第一阶段访问方式。
- 允许在隔离的 Webots 仿真中进行参数优化和后续强化学习实验，但真实小车仍受人工审批和安全边界约束。

## 2. 已确认目标

### 2.1 用户体验

操作者登录 `8.ilelezhan.cn` 后，在同一主界面完成：

1. 选择“仿真模式”或“真实小车模式”。
2. 取得控制权。
3. 选择地图、车体、参数版本和任务配置。
4. 执行预检并重置小车、地图、计时器和任务日志。
5. 点击“开始自动探索”。
6. 实时观看 Webots 或真实相机画面。
7. 同时查看迷宫格位置、连续坐标、车头方向、航向角、定位置信度、传感器、姿态、摩擦/滑移指标和当前参数。
8. 观察自动修正、模型建议和参数版本变化。
9. 到达终点后查看成绩、轨迹、关键事件和同步回放。
10. 将表现好的参数标记为稳定版本，或回滚到历史版本。

### 2.2 双用户规则

- 两名参与者使用独立网站账户。
- 同一时间只有一名用户持有控制权租约，可以开始、暂停、停止、重置、切换模式和审批实车参数。
- 未持有控制权的用户为只读观看者。
- 所有已登录用户始终可以触发急停。
- 只有当前操作者在完成现场检查和完整预检后才能清除急停。
- 控制权取得、续租、释放、过期、抢占请求和所有控制操作必须写入审计日志。

## 3. 不变的硬件职责

### 3.1 RDK X3

负责：

- 相机和高级感知。
- 迷宫建图、定位融合、动作决策和路径规划。
- 与服务器的加密连接。
- 与 ESP32 的串口通信。
- 断云后的本地停止策略。
- 将结构化遥测、视频、动作结果和日志发送给服务器。

### 3.2 ESP32

负责：

- 电机 PWM、编码器、三向 VL53LXX 和 IMU 采集。
- 5–10 ms 运动控制 tick。
- PID 和非阻塞动作状态机。
- `action_id` 对应的 `ack`、`done` 和 `error`。
- 急停、前方过近、动作超时、心跳超时、参数限幅和串口解析容错。

服务器或模型不得以高频率发送左右轮 PWM。云端断开、Python 卡死或网页关闭时，ESP32 必须仍能独立停车。

## 4. 总体架构

```text
浏览器
└── https://8.ilelezhan.cn
    ├── 登录与控制权
    ├── 仿真/实车模式
    ├── 迷宫编辑器
    ├── 实时画面与遥测
    ├── 参数工作台
    └── 成绩与回放
             │ HTTPS / WSS
             ▼
腾讯云 FastAPI 平台
├── AuthService / ControlLease
├── TaskOrchestrator
├── ModeGuard
├── AgentGateway
├── ParamVersionStore / LLMAdvisor / Optimizer
├── ScoreEngine / ReplayService
├── SQLite 索引
├── JSONL 事件
└── 视频与导出文件
       │                         │
       │ 仿真模式                │ 真实小车模式：加密 WSS
       ▼                         ▼
Webots R2025a                RDK X3 Agent
├── 仿真真值                  ├── 相机与视觉
├── 编码器/ToF/IMU 模型       ├── PoseFusion / MazeRunner
├── 摩擦/噪声/轮滑场景        ├── 本地规则补偿 / ParamApplier
├── PoseFusion / MazeRunner   └── pyserial
└── ESP32 同构 JSON 协议           ▼
                                 ESP32
                                 ├── PID/编码器/ToF/IMU
                                 └── 电机与本地安全
```

`PoseFusion`、`MazeMap`、`MazePlanner`、`MazeRunner` 和规则型补偿属于共享 Python 核心：仿真模式在服务器的仿真进程运行，真实小车模式在 RDK X3 本地运行。服务器在实车模式只保存其镜像状态、任务记录和参数候选，不把公网延迟放入逐动作决策闭环。

### 4.1 统一协议

仿真适配器和真实 ESP32 使用相同的一行一个 JSON 协议，继续遵守：

- 所有动作具有唯一 `action_id`。
- 地图位置只在收到对应 `done` 后推进。
- `error` 不推进地图。
- telemetry 包含状态、传感器、编码器、姿态、当前参数版本和质量标记。
- 模式切换时两个 transport 不得同时具有命令发送权。

### 4.2 模块边界

- `TaskOrchestrator` 管理任务状态；实车模式只发送开始、暂停、停止、急停和已审批参数版本，不参与逐动作规划，更不计算 PWM。
- `PoseFusion` 只消费传感器和动作结果，不直接访问网页或串口。
- `MazePlanner` 只根据地图和位姿生成计划。
- 服务器 `ParamVersionStore` 管理候选和审批；RDK `ParamApplier` 再做本地白名单和范围校验，并作为真实小车写入 ESP32 的唯一入口；ESP32 最终再次限幅。
- RDK `LocalRuleTuner` 可以按已批准规则生成并通过 `ParamApplier` 应用小幅补偿；服务器 `LLMAdvisor` 和 `Optimizer` 只能生成候选变更。
- `ReplayService` 只记录和读取事件，不反向改变运行状态。
- `AgentGateway` 鉴权 RDK 设备并转发统一协议，不解析模型建议。

## 5. 网站主界面

### 5.1 顶部固定区域

始终显示：

- 当前模式：仿真或真实小车。
- 当前任务、地图和参数版本。
- RDK/ESP32/Webots 在线状态。
- 当前控制权持有人和剩余租约时间。
- 急停按钮。

运动中禁止直接切换模式。切换必须先安全停车并回到 `IDLE` 或 `COMPLETED`。

### 5.2 主画面

- 仿真模式嵌入经过网站鉴权的 Webots 浏览器流。
- 真实模式第一版由 RDK 以自适应的 640×360、5–10 FPS JPEG 帧通过同一条鉴权 WSS 上传，服务器限制视频数据不超过 3 Mbps，并转发给浏览器。服务器使用 ffmpeg 将帧和统一时间戳封装为回放 MP4；后续可以在不改变任务协议的情况下替换为 H.264。
- 画面叠加任务时间、运行状态、估值/真值误差、航向误差、视频状态和网络延迟。
- 仿真真值只用于显示、评分和评估，不作为定位算法的输入，避免算法“作弊”。

### 5.3 操作按钮

- 开始自动探索。
- 暂停。
- 停止。
- 重置。
- 急停。

“开始”只有在地图、模式、控制权、服务、设备、传感器、参数和存储预检全部通过后才可用。暂停必须先完成安全停车，不是简单冻结网页或 Webots 画面。

### 5.4 定位和地图区域

同时显示：

- 可靠主定位：迷宫格坐标和主方向。
- 连续估算：`x/y` 厘米、航向角和速度。
- 定位置信度。
- 估算协方差或误差范围。
- 当前格、已探索区域、墙体、路径、目标和历史轨迹。
- 最近一次定位修正的原因和修正量。

### 5.5 技术参数工作台

Webots/实车画面下方显示以下分组。

车辆和环境：

- 车体质量。
- 轮半径和轮距。
- 电池电压。
- 仿真摩擦系数。
- 实车等效摩擦/滑移指标。
- 左右轮滑移率。
- 地面坡度或姿态异常。

运动参数：

- `base_speed`、`turn_speed`。
- `cell_ticks`、`turn_90_ticks`。
- 速度 PID。
- 航向和墙面跟随增益。
- 加速度限制和 PWM 上限。
- 停车容差。

实时证据：

- 前/左/右 ToF。
- 左右编码器。
- IMU yaw 和 yaw rate。
- 墙面拟合残差。
- 定位协方差。
- 串口丢包和云端延迟。
- 当前动作、`action_id` 和动作剩余时间。

可编辑参数必须显示单位、当前值、允许范围、来源和当前版本。修改先形成差异预览，再由 `ParamManager` 校验和下发。

## 6. 迷宫描线编辑器

### 6.1 第一版范围

只支持规则格子迷宫，不支持斜墙、曲线和非规则开放场地。

默认使用“格线吸附描墙”：

- 鼠标或触控板沿单元格边缘拖动画墙。
- 支持擦除、撤销、重做。
- 设置起点、终点和初始车头方向。
- 设置行列数、每格尺寸、墙厚和墙高。
- 自动吸附为水平或垂直墙段。

保留“导入图片描摹”：

- 上传实体迷宫照片或平面图作为半透明底图。
- 用户标定两个已知点或一个已知长度。
- 在底图上按格线吸附方式描墙。
- 图片本身不是规划地图，保存前必须转换为结构化墙体。

### 6.2 结构化地图

地图保存为不可变版本，至少包含：

```json
{
  "map_id": "maze-lab-01",
  "version": 4,
  "rows": 5,
  "cols": 6,
  "cell_width_mm": 300,
  "cell_height_mm": 300,
  "wall_thickness_mm": 18,
  "wall_height_mm": 120,
  "start": {"x": 0, "y": 4, "heading": "N"},
  "goals": [{"x": 5, "y": 0}],
  "walls": [],
  "source_image_digest": null,
  "content_digest": "..."
}
```

保存前必须检查：

- 外边界闭合。
- 墙体吸附、去重和无零长度线段。
- 起点和终点位于有效单元格。
- 起点和终点存在可达路径。
- 墙距和通道宽度满足小车外形和传感器量程要求。

同一地图版本编译为：

- Webots 世界中的墙体。
- `MazeMap` 使用的墙体邻接关系。
- 实车定位的先验地图。
- 回放和评分使用的地图快照。

保存新版本不得覆盖历史运行所引用的旧版本。

## 7. 定位、方向和摩擦/空转修正

### 7.1 双层位置表示

第一层是可靠离散状态：

- 迷宫格坐标。
- 东、南、西、北主方向。
- 只在动作完成和校验后改变。

第二层是连续估算状态：

- `x`、`y` 毫米。
- `yaw` 角度。
- 线速度和角速度。
- 协方差和置信度。

### 7.2 融合方法

第一版使用可测试的扩展卡尔曼滤波或等价状态估计器：

1. 编码器里程计提供预测。
2. IMU yaw/yaw rate 抑制转向漂移。
3. 前/左/右 ToF 与已知墙面约束修正横向位置、停车距离和航向。
4. 动作 `done` 将连续估值与格子边界进行一致性检查。
5. 可选视觉终点/标志识别提供任务事件；第一版视觉不进入电机高频闭环。

实车连续航向验收要求接入一块 I²C 六轴 IMU，并通过统一 `ImuDriver` 提供 yaw rate 和加速度。具体模块与引脚只能在核对现有小车实物和 I²C 总线后写入硬件配置，不能在未验证时覆盖当前 pin map。未接入 IMU 时网站必须显示 `imu_available=false`，系统可以使用格子主定位和编码器/ToF 降级运行，但不能宣称通过连续航向精度验收。

### 7.3 实车摩擦和滑移

真实地面的摩擦系数不能由现有传感器直接精确测得，网页必须标记为“估算”而不是物理真值。系统使用：

- 编码器预测位移。
- IMU 加速度和航向变化。
- ToF 到墙距离变化。
- 动作完成误差。
- 可选相机光流。

推断左右轮滑移和等效摩擦状态。检测到空转、偏航或停车不足时：

- 优先降低速度和加速度。
- 有限调整左右轮补偿、航向增益、墙面跟随增益和动作目标。
- 单次实车自动变化受百分比和绝对范围双重限制。
- 变化后观察后续动作，恶化则立即回滚。

当定位置信度低于阈值时，连续坐标显示为低可信；系统停止下发新动作并尝试利用墙面、IMU 和已知格边重新定位。无法恢复时结束任务，不自动盲走。

## 8. 调参体系

### 8.1 手动调参

操作者可以编辑白名单参数。每次提交必须：

1. 显示旧值、新值、单位和允许范围。
2. 说明适用模式和作用域。
3. 生成不可变候选版本。
4. 经 `ParamManager` 校验。
5. 下发成功后记录 ESP32 ack。
6. 失败时保持旧版本为当前版本。

### 8.2 规则型在线调参

规则引擎读取动作误差、滑移率、IMU 偏航、ToF 墙面残差和历史趋势。仿真模式由服务器仿真进程运行；实车模式由 RDK 的 `LocalRuleTuner` 本地运行，避免依赖公网往返。

- 仿真中可在参数范围内自动应用和试跑。
- 实车中只能调整非安全运动参数。
- 实车单次变化默认不超过当前值的 5%，且受绝对范围限制。
- 每次变化必须包含触发证据、规则 ID、旧值、新值和观察窗口。
- 观察窗口内成绩或稳定性下降时自动回滚。

### 8.3 模型建议

实现提供商无关的 `LLMAdvisor` 接口，可接入经过配置的 OpenAI/Codex 系列、DeepSeek 或 K 系列模型 API。交互式 Codex 仍是开发与诊断助手；服务器只有在配置了正式 API 凭据和适配器时才运行常驻模型建议，不依赖当前聊天会话。模型接收：

- 脱敏后的串口和任务摘要。
- 位姿、动作误差和传感器质量。
- 当前参数、历史版本和得分。
- 失败回放的结构化关键事件。

模型只允许返回符合 JSON Schema 的候选：

```json
{
  "changes": {"motion.speed_kd": 0.062},
  "evidence": ["right-wall oscillation in 8 actions"],
  "expected_effect": "reduce overshoot",
  "risk": "may slow response",
  "recommended_trials": 10
}
```

模型不得直接发送动作、PWM 或串口消息。输出必须经过：

- 参数白名单。
- 类型和范围校验。
- 安全参数拒绝。
- 当前模式权限校验。
- 新版本生成。
- 仿真试跑或人工审批。

模型 API 密钥只保存在服务器受限环境文件中，不进入浏览器、代码仓库和回放日志。串口、网页文本和模型回复都视为不可信输入。

### 8.4 仿真优化和强化学习

低维 PID、速度、动作目标和墙面跟随参数优先使用贝叶斯优化或 CMA-ES，原因是样本效率和可解释性优于直接使用强化学习。

强化学习留给后续高层策略，例如探索顺序或复杂决策，不直接输出 PWM。所有训练只在隔离的 Webots headless 批次中进行。

每个候选必须经过：

- 多个迷宫。
- 多个摩擦系数。
- 多档传感器噪声。
- 左右轮不一致和轮滑场景。
- 障碍、定位丢失和超时故障注入。

仿真候选只有在零安全违规且综合指标稳定改善后，才能成为“待实车验证”版本；不得自动晋级为实车稳定版。

### 8.5 不可自动修改的参数

以下参数属于安全域，任何规则、模型、优化器或强化学习都不能静默修改：

- 急停逻辑。
- 心跳超时。
- 危险距离和前方立即停车阈值。
- 动作硬超时。
- 最大 PWM 和硬件电流/速度上限。
- 参数绝对范围。
- 串口解析失败后的停车策略。

## 9. 参数版本和实验谱系

每个参数版本不可变，包含：

- 版本 ID 和内容摘要。
- 父版本。
- 参数完整快照和差异。
- 来源：人工、规则、模型、优化器或恢复。
- 触发证据和审批人。
- 适用模式、车体 ID、地面档案、地图和固件范围。
- 代码提交、固件版本、模型提供商与模型版本。
- 仿真和实车运行结果。
- 状态：候选、仿真通过、待实车验证、实车稳定、退役或拒绝。

不存在脱离场景的“全局最佳参数”。排行榜至少按以下域隔离：

- 仿真或实车。
- 车体 ID。
- 固件和硬件标定。
- 地面/摩擦档案。
- 地图类型。

任一历史稳定版本都可以恢复，但恢复动作本身也生成新的审计事件。

## 10. 任务状态机

状态包括：

- `IDLE`：空闲，可切换模式。
- `PREFLIGHT`：检查控制权、地图、服务、设备、传感器、参数和存储。
- `READY`：已重置，等待开始。
- `RUNNING`：自动探索。
- `PAUSING`：正在安全停车。
- `PAUSED`：已停车，保留遥测和定位。
- `FINALIZING`：停止设备并冻结最后状态。
- `COMPLETED`：已完成计分。
- `LOST`：云端或 RDK 连接丢失。
- `ERROR`：动作或系统错误。
- `ESTOP`：急停锁定。

一次动作内部流程：

1. 感知。
2. 定位融合。
3. 地图和路径规划。
4. 生成带 `action_id` 的动作。
5. ESP32 本地执行。
6. 等待匹配的 `done` 或 `error`。
7. 更新地图、位姿、评分中间量和调参证据。

规则：

- `RUNNING`、`PAUSED`、`LOST`、`ERROR` 和 `ESTOP` 中禁止切换模式。
- 暂停必须先安全停车。
- 断网、急停或严重错误后禁止自动续跑。
- 恢复前必须重新取得控制权并通过完整预检。

## 11. 异常处理

### 11.1 定位置信度过低

- 停止生成新动作。
- 标记连续位置为低可信。
- 尝试墙面、IMU 和格边重定位。
- 成功后由操作者继续；失败则结束任务。

### 11.2 云端或 RDK 断联

- RDK 发现断云后立即下发 `stop`。
- 如果 RDK 进程卡死，ESP32 因心跳超时独立停车。
- 网页进入 `LOST`，重连后不得自动续跑。

### 11.3 障碍和动作超时

- ESP32 本地停车并返回 `error`。
- 冻结对应动作的传感器、参数和定位证据。
- 排障后从预检开始，或结束任务。

### 11.4 急停

- 所有已登录用户都能急停。
- 急停优先级高于其他命令。
- 只有当前操作者完成现场检查后才能 `clear_estop`。
- `clear_estop` 后仍需完整预检。

### 11.5 模型或优化器异常

- 超时、无效 JSON、越界参数、安全参数和证据不足的建议全部拒绝。
- 提供商不可用不影响手动、规则、仿真或实车基础功能。
- 模型建议失败不得改变当前参数版本。

## 12. 成绩、记录和回放

### 12.1 原始指标

原始指标不可因计分权重变化而覆盖，至少包括：

- 任务完成和终点状态。
- 地图墙体准确率。
- 格子定位准确率。
- 连续位置 RMSE。
- 航向角 MAE。
- 路径长度和相对最优路径倍率。
- 总时间。
- 停车误差 P95。
- 最大/平均滑移率。
- 动作成功率和重试次数。
- 碰撞、越界、超时、急停和安全事件。

### 12.2 默认计分档案

`score-profile-v1` 使用：

- 完成与终点：35 分。
- 地图准确率：20 分。
- 定位与方向：15 分。
- 路径和时间：12 分。
- 动作精度：8 分。
- 安全与稳定：10 分。

正式比赛规则到位后创建新的计分档案版本，不修改历史原始指标。

### 12.3 同步回放

回放按统一单调时间戳同步：

- Webots 或真实相机视频。
- 迷宫地图和轨迹。
- 连续位姿、方向和置信度。
- 传感器和编码器。
- 动作、ack、done、error。
- 参数变化和审批。
- 模型建议和优化批次。
- 控制权和安全事件。

关键事件可以点击跳转到对应画面和参数状态。

### 12.4 存储

- SQLite：用户、设备、任务、地图、参数版本、成绩、审批和文件索引。
- JSONL：不可变事件流和原始证据。
- 媒体：Webots/真实相机录像和缩略图。
- 导出：任务报告、地图、参数包和回放清单。

默认保留策略：

- 普通视频保留 30 天。
- 原始 JSONL 和指标保留 180 天。
- 标记为最佳、基准、事故或比赛证据的运行长期保留。
- 清理任务只删除符合策略的媒体，不删除仍被参数版本或正式报告引用的证据。

## 13. 公网访问和安全

### 13.1 入口

- 域名：`8.ilelezhan.cn`。
- TCP 80 只用于跳转 HTTPS 和证书流程。
- TCP 443 提供网站、API 和 WSS。
- TCP 22 保留 SSH 管理。
- 8000、1234、6080、5901、8765 等内部端口继续监听回环地址或由 UFW 拒绝公网。

第一版使用 Caddy 终止 TLS、自动续期证书，并将页面、API、WebSocket 和 Webots 流统一代理到经过鉴权的路径。noVNC 仅用于管理调试，不作为普通用户功能。

### 13.2 网站账户

- 两名参与者使用独立账户。
- 密码使用 Argon2 哈希。
- 使用 Secure、HttpOnly、SameSite 会话 Cookie。
- 状态改变请求具备 CSRF 防护。
- 登录和敏感操作限速。
- 控制权租约每 5 秒续约，默认 15 秒过期。
- 观看者不能通过直接调用 API 绕过只读限制。

### 13.3 RDK 设备认证

- RDK Agent 主动通过 WSS 连接服务器。
- 每台设备使用可吊销、可轮换、绑定设备 ID 的令牌。
- 设备令牌与网站用户会话分离。
- 串口设备和局域网端口不直接转发到公网。

### 13.4 服务与秘密

- 服务以无 sudo 的 `maze` 账户运行。
- 部署和系统维护使用 `ubuntu` 账户。
- SSH 同时保留已验证公钥和密码登录，除非用户后续另行授权变更。
- 模型密钥、设备令牌和网站密钥放入权限受限的服务器环境文件。
- 秘密不写入 Git、JSONL、SQLite 普通字段、浏览器响应或诊断包。

## 16. 第一版验收标准

### 16.1 功能

- 网站登录和双用户观看成功。
- 控制权规则和共同急停成功。
- 仿真/实车只能在安全状态切换。
- 迷宫描线、保存、版本和 Webots 编译成功。
- 一键重置、开始、自动探索、完成、成绩和回放闭环成功。
- 仿真和实车使用同构动作协议。
- 高分运行可恢复对应代码、固件、地图、参数和证据。

### 16.2 实时性

- 页面遥测目标 10–20 Hz。
- CPU Webots 浏览器画面目标 8–15 FPS，记录实测值，不伪造 GPU 级效果。
- 控制权心跳 5 秒，15 秒过期。
- ESP32 运动控制 tick 维持 5–10 ms。
- 急停和断联停车延迟必须分别在台架上测量并写入验收报告；云端网络延迟不得作为本地停车成立的前提。

### 16.3 安全

- 80/443/22 之外的内部服务端口不暴露公网。
- 观看者不能绕过 API 权限控制。
- 模型不能直接动作或修改安全参数。
- 断云、断串口、前方过近、动作超时和急停均存在独立停车路径。
- 密钥和令牌不进入仓库、浏览器或回放。

### 16.4 质量

- Python `compileall` 通过。
- Python 全部测试通过。
- ESP32 PlatformIO 构建通过。
- 浏览器端关键流程自动化测试通过。
- systemd 服务重启和版本回滚通过。
- 失败候选不污染稳定参数版本。

## 17. 第一版非目标

- 不支持不规则、斜墙和曲线迷宫。
- 不让模型或强化学习直接输出电机 PWM。
- 不让仿真结果替代真实硬件验收。
- 不把 Webots 真值输入定位算法。
- 不在第一版实现多车并发控制。
- 不将 noVNC 暴露为普通用户功能。
- 不保证 CPU 服务器达到 GPU 渲染帧率。
- 不允许自动调参修改安全参数。

## 18. 回滚和降级

- 网站新版本失败：切回 `/srv/maze/releases` 的上一版本。
- Webots 浏览器流失败：保留 headless 仿真和地图/遥测显示，并记录真实错误。
- 模型提供商失败：关闭模型建议，保留手动、规则和优化器功能。
- RDK 断云：本地停车并保留 ESP32 安全闭环。
- 参数恶化：恢复上一稳定参数版本。
- 视频记录失败：任务可以继续，但标记“媒体证据不完整”，不能作为完整比赛证据样本。
- 磁盘接近阈值：停止新录像和批量仿真，保留控制与急停能力，并通知管理员。

## 19. 实施顺序约束

后续实施计划必须按可验证的最小闭环推进：

1. 账户、控制权和 HTTPS。
2. 任务状态机与仿真重置/开始/停止。
3. 主界面实时画面和统一遥测。
4. 迷宫描线和地图版本。
5. 定位融合与误差显示。
6. 成绩、JSONL、视频和回放。
7. RDK Agent 和实车模式。
8. 手动/规则调参与参数版本。
9. 模型建议。
10. 仿真批量优化和后续强化学习。

在完成前一个阶段的测试和证据之前，不同时大改协议、定位、调参和 UI。
