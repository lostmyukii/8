# 安全地图任务重置修复设计

日期：2026-08-02

## 背景

生产站点中，用户把地图下拉框切换为其他版本后，页面仍可能复用旧任务。
旧任务保存的是创建时的不可变地图版本，因此 Webots 实际收到的仍可能是窄通道地图。
同时，物理通道预检返回失败时，前端仍继续调用重置；后端重置接口也只检查存在预检结果，
没有检查该结果是否成功。

## 已确认方案

采用三层修复：

1. 页面提交重置前，对比当前选择与任务保存的不可变输入。
   地图版本、参数版本、目标格、模式或物理配置任一变化时，创建新任务。
2. 页面先等待预检结果；只有 `preflight_result.ok === true` 才调用重置。
   不安全时显示净通道尺寸和最低要求，不创建运行记录、不启动 Webots。
3. 后端 `reset` 再次强制要求成功预检，防止旧页面或直接 API 请求绕过前端。

不安全预检后的任务保持在 `PREFLIGHT`，但页面允许再次点击“预检并重置”。
用户改选安全地图后，页面会创建新任务并重新预检。

## 错误信息

物理通道不安全时返回可操作的中文信息：

`物理通道不安全：净通道 X × Y mm，至少需要 Z mm`

结构化的 `physical_preflight` 数据继续保留，便于页面和自动化测试读取。

## 验证

严格执行以下顺序：

1. 先增加失败测试，证明不安全预检不能重置。
2. 增加页面静态契约测试，覆盖不可变输入变化、预检阻断和重试按钮。
3. 实现最小修复并运行定向测试。
4. 运行完整 Python、Dashboard、PlatformIO 和 Webots P1-P4 回归。
5. 独立提交、推送并部署正式站点。
6. 在正式站点选择已验证安全地图，重置并启动；以遥测位置或步数变化证明小车运动，
   随后安全停止。

## 边界

- 本修复不降低物理通道最低宽度，不修改急停、超时或安全参数。
- 生产浏览器成功只证明仿真闭环；真实小车仍需单独完成硬件验收。
- 不记录登录密码、服务器密钥或设备路径。
